# 视频隐私打码算法说明

## 1. 当前集群默认算法

当前 Controller + Worker 集群默认运行 `video_mask_batch_fish_v1.py`，定位为**仅人脸的视频隐私打码**，并针对广角/鱼眼来源视频提供可选的去畸变预处理。

集群默认任务参数为：

```text
--fisheye --fisheye-device pico4
--face-size 640 --face-conf 0.35 --face-int 5 --frame-skip 2
--face-model yolov8
```

这表示：使用 Pico 4 鱼眼预置进行画面校正，以 640 输入尺寸、0.35 置信度阈值进行人脸检测，每 5 帧进行一次检测并在中间帧跟踪；默认每 2 帧处理一次以提升处理速度；人脸检测器采用 YOLOv8-nano 人脸模型。上述参数可以按客户相机、漏检风险和时效要求逐项调整。

## 2. 处理流程

```text
输入视频
   │
   ├─ FFmpeg 解码为内存中的原始视频帧
   │
   ├─（可选）鱼眼/广角去畸变
   │
   ├─ 关键帧人脸检测：YuNet 或 YOLOv8-nano
   │
   ├─ 中间帧 LK 光流跟踪，保持人脸框连续
   │
   ├─ 对人脸区域外扩后执行“高斯模糊 + 像素化马赛克”
   │
   └─ FFmpeg 编码视频并保留原音轨 → 输出 MP4
```

视频帧在 FFmpeg 与算法进程之间通过内存管道流转，不需要生成大量临时图片。支持时会自动使用可用的硬件加速能力，例如 NVIDIA NVDEC 解码和 NVENC 编码；不可用时会自动回退到软件处理路径。

## 3. 人脸检测与跟踪

| 能力 | 当前实现 | 客户价值 |
|---|---|---|
| 检测模型 | YuNet（轻量、依赖少）或 YOLOv8-nano 人脸模型（集群默认） | 可按速度、部署条件和样片效果选择 |
| 关键帧检测 | 按可配置间隔重新检测人脸 | 降低逐帧深度推理的计算压力 |
| 帧间跟踪 | Lucas–Kanade（LK）光流跟踪 | 在相邻画面中保持打码区域连续，减少闪烁 |
| 漏检缓冲 | 短时沿用最近有效人脸框 | 应对个别帧的短暂检测波动 |
| 打码区域 | 在检测框周围按比例外扩 | 尽量覆盖完整人脸边缘，降低局部未遮盖风险 |
| 打码效果 | 高斯模糊后像素化 | 同时削弱面部纹理与轮廓细节 |

检测间隔越小，通常越有利于快速运动或镜头切换场景的覆盖连续性，但耗时会增加；抽帧跳过值越大，处理速度会提高，但对于高运动场景可能降低时间连续性。生产参数应通过客户典型样片进行平衡。

## 4. 广角与鱼眼视频支持

对于 VR、运动相机或广角镜头视频，图像边缘的人脸会因桶形畸变而变形，影响检测效果。默认算法可在检测前进行鱼眼去畸变：

- 提供通用鱼眼预置和 Pico 4 预置；
- 对同一分辨率缓存映射关系，降低重复计算；
- 可选择降低去畸变处理分辨率以换取更高速度；
- 该功能是基于预置参数的图像校正，并非针对每台相机完成的标定方案。

如客户使用特定型号摄像头且对画面几何精度有要求，建议提供样片和相机标定参数，以便进行专项验证与参数调优。

## 5. 银行卡/信用卡打码能力

项目另提供 `video_mask_batch_skip.py` 通用算法，可在**人脸之外检测银行卡/信用卡并打码**。该能力不是当前集群默认任务脚本；如客户需要，应在上线配置中明确切换算法、安装相应依赖并做样片验收。

| 模式 | 方法 | 特点 | 适用建议 |
|---|---|---|---|
| 高精度卡片模式 | OWLv2 零样本视觉检测 + LK 光流跟踪 | 面向信用卡、银行卡等文本提示进行检测；首次使用需要准备模型 | 卡片颜色、样式较多，或有一定遮挡的场景；须样片验证 |
| 快速卡片模式 | 几何轮廓/长宽比规则，可叠加颜色提示 | 资源开销较低，但依赖卡片边缘和形状可见 | 卡片完整、边界明显、背景相对简单的场景 |

卡片检测受遮挡、反光、画面中卡片尺寸、旋转角度、背景纹理和运动模糊影响较大。对于银行卡、证件号等高敏感信息，建议将自动处理作为第一道防护，并根据业务风险设计抽检或人工复核流程。

## 6. 输入输出与媒体处理特性

- 支持常见视频格式作为输入，包括 MP4、MOV、AVI、MKV、WebM 等；
- 输出为 MP4 格式，默认文件名带有 `masked_` 前缀；
- 使用 FFmpeg 进行媒体解码与封装；当输入包含音频且环境支持时，输出会保留原音轨；
- 支持 NVIDIA GPU 的推理/编解码可用性探测，并在硬件能力不满足时使用兼容路径；
- 集群 Worker 会在本地独立工作目录处理文件，完成并上传成功后向 Controller 上报结果。

## 7. 参数调优与验收建议

建议客户以真实业务视频建立验收样本集，覆盖不同光线、距离、人数、快速运动、遮挡、侧脸、广角边缘、不同分辨率和不同摄像头。可重点评估：

| 目标 | 可调整项 | 取舍 |
|---|---|---|
| 提高快速运动下的覆盖 | 降低 `--face-int`，降低或关闭 `--frame-skip` | 算力和处理时长增加 |
| 提高小脸/远距离人脸召回 | 提高 `--face-size`，选用合适的人脸模型 | 速度和显存开销增加 |
| 提升吞吐 | 提高 `--frame-skip`、适当增加检测间隔、扩充 GPU Worker | 需验证连续性与漏检风险 |
| 处理鱼眼画面 | 启用鱼眼预置并调节校正强度/降采样 | 需针对相机样片验证几何效果 |
| 增加卡片保护 | 切换至含卡片检测的通用算法 | 增加模型和算力需求，必须做场景验收 |

## 8. 使用边界与风险说明

本系统提供自动化视频隐私打码能力，但不应将其表述为对所有画面、所有角度和所有输入质量的绝对零漏检保证。模型效果需以客户的真实数据集、部署硬件和最终参数为准。

在上线前，建议完成以下工作：

1. 使用客户典型样片进行效果与吞吐压测；
2. 固化验收参数、算法脚本版本和模型版本；
3. 对高敏感业务设置抽样质检、异常复核或人工处理流程；
4. 定期以新增场景样本复测，必要时调整参数或模型选择。
