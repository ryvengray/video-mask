# 双鱼眼人脸预检可行性报告

测试日期：2026-08-25  
测试集：`tests/prescan`  
目标：确定是否可在正式打码前预检视频；当视频确认无脸时，跳过完整打码与重编码，直接复制/remux。

## 1. 数据与测试协议

| 类型 | 文件 | 时长 | 说明 |
| --- | --- | ---: | --- |
| 含脸 | `hasface_20260815_051315.mp4` | 57.62 秒 | 画面内有真实人员脸部 |
| 无脸 | `noface_20260815_121125.mp4` | 163.95 秒 | 用户确认无人脸 |
| 无脸 | `noface_20260816_023954.mp4` | 56.02 秒 | 用户确认无人脸 |
| 无脸 | `noface_20260816_053126.mp4` | 133.83 秒 | 用户确认无人脸 |

统一处理链：顺序读到视频 EOF、每秒抽样 5 帧、原始双鱼眼缩放为每目最大 640px、左右眼独立按 Pico4 参数去畸变、左右眼独立推理。每个命中秒均保存一张标注截图供人工复核。

Mac 环境没有可用的 CoreML 编译缓存，因此本次为 CPU 测试；NVIDIA 服务器应通过 `--device cuda` 使用 CUDA。模型的相对精度结论与后端无关，绝对速度需在服务器复测。

## 2. 模型对比

“无脸最高分”取三段无脸视频中任意命中秒的最大分数；只有当阈值严格高于该值时，这一小批无脸视频才会全部被判为可跳过。

| 模型与输入 | 含脸视频最高分 | 无脸最高分 | 当前样本中可分离阈值 | 结果 |
| --- | ---: | ---: | ---: | --- |
| SCRFD-2.5g / 320 | 0.657 | 0.620 | >0.620 | 高分框多落在衣物/家具，不可靠 |
| SCRFD-10g / 320 | 0.684 | 0.595 | >0.595 | 高分框仍常落在门窗纹理，不能验证真脸召回 |
| YOLOv8-nano-face / 320 | 0.684 | 0.741 | 不存在 | 无脸分数超过含脸最高分，淘汰 |
| YOLOv8-nano-face / 640 | 0.748 | 0.601 | 0.625 | 最好：截图确认高分框命中真实脸 |
| YOLOv8-medium-face / 640 | 0.816 | 0.736 | 0.750 | 可分离但更慢，且无脸高分误报更高 |

### 关键证据

- SCRFD 10g 的高分候选曾落在门窗/墙面纹理，未稳定框住画面内的真实人员脸部，因此不能仅凭“该视频有命中”视为真脸检出。
- YOLOv8-nano/640 在有人脸样本中实际框住了站立人员的人脸，最高分 `0.748`；三段无脸视频的最高误报分别为 `0.548`、`0.448`、`0.601`。
- YOLOv8-medium/640 在一段无脸视频中对非脸目标给出 `0.736`，说明更大模型并不必然更适合作为此鱼眼场景的预检模型。

## 3. 阈值结果

### 推荐候选：YOLOv8-nano-face / 640

| 阈值 | 含脸视频命中秒 | 无脸视频命中情况 |
| ---: | ---: | --- |
| 0.50 | 18 | 3 段均有误报 |
| 0.60 | 12 | 1 段有 1 个误报秒（0.601） |
| **0.625** | **12** | **3 段均为 0** |
| 0.65 | 9 | 3 段均为 0 |
| 0.70 | 4 | 3 段均为 0 |

在这批测试集内，`0.625` 是最小的无脸全通过阈值，并且保留 12 个有人脸命中秒；`0.65` 有更多误报余量，但会牺牲部分低分真脸候选。

## 4. 可行性结论

### 架构上可行，但尚不能直接作为生产“自动跳过”开关

该场景中 75% 的视频无脸，预检若可靠，能够避免无脸视频的逐帧打码和重新编码，收益很大。因此“视频级预检 + 无脸直通”在架构与成本上是合理的。

但目前只有 1 段含脸样本，且以 5 fps 抽样；它不足以证明以下高风险情况不会漏检：极短露脸、小脸、强侧脸、遮挡脸、运动模糊、鱼眼边缘脸。因此，当前结果只能支持 **shadow / 灰度验证**，不支持直接将无命中视频自动跳过正式打码。

### 灰度阶段推荐实施参数

```text
模型：YOLOv8-nano-face（yolov8n-face.pt）
双眼：左右眼各自去畸变、各自推理
YOLO 输入：640
预检每目最大宽度：640
鱼眼参数：pico4，strength=1.0，crop=1.0
候选阈值：0.625
抽样：5 fps（仅用于当前灰度验证）
服务器后端：CUDA
决策：任一只眼、任一抽样帧命中 → 运行原生产打码；全程无命中 → 标记为“候选跳过”
```

对应命令：

```bash
python prescan_dual_fisheye_scrfd.py tests/prescan \
  --model yolov8 --input-size 640 --screen-eye-width 640 \
  --confidence 0.625 --sample-fps 5 --fisheye-device pico4 \
  --device cuda --out-dir tests/prescan/yolo640_shadow
```

### 生产准入条件

1. 收集至少 50 段含脸双鱼眼视频，必须覆盖短暂露脸、小脸、侧脸、遮挡、边缘、暗光和快速运动。
2. 灰度期间，所有“候选跳过”视频仍完整运行现有生产打码算法，用生产结果反查预检是否漏掉任何含脸视频。
3. 只有在视频级漏检数为 `0` 时，才允许将“候选跳过”切换为真正的复制/remux 跳过。
4. 上线前将抽样率提升到逐帧，或基于标注数据证明 5 fps 对最短露脸时长仍满足零漏检要求；否则 5 fps 不适用于隐私安全的最终判定。
5. 在 NVIDIA 服务器上测量 CUDA 吞吐和端到端收益，确认预检成本显著小于完整打码成本。

## 5. 最终建议

**推荐继续推进预检，但以 YOLOv8-nano-face / 640 / 双眼独立去畸变为唯一灰度候选；不推荐 SCRFD 单模型，也不推荐 YOLOv8-medium。**

参数 `0.625` 仅是当前样本集的起始灰度阈值，不是最终隐私阈值。正式启用“无脸跳过”前，必须先完成上述含脸集的零漏检验证。
